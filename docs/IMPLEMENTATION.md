# 구현 범위

요청: 기존 Markdown 명세에 맞춰 저장소를 구성한다.

## Phase 0

- `apps/web`: Vue 3 + TypeScript + Quasar PWA. 환영·로그인·초대 가입·온보딩·오늘·설정.
- `services/api`: Java 21 + Spring Boot. PostgreSQL/Flyway, 세션 인증·CSRF, 사용자 프로필.
- `infra`, `scripts`: PostgreSQL/API/Web 로컬 Compose, 동일 출처 프록시, HTTPS 운영 구성.
- `.github`: 백엔드 테스트/빌드, 프런트 린트/타입검사/테스트/빌드.

## 수용 기준

1. 빈 DB에서 마이그레이션, 초대 가입 → 로그인 → 세션 → 설정 → 로그아웃.
2. 미인증 개인 API 및 화면 차단. CSRF 없는 변경 차단. 다른 계정의 프로필 격리.
3. 로그인 실패와 서버 장애 구분. 외부 URL로 로그인 리다이렉트 금지.
4. 프런트 빌드, 타입·린트, 인증 테스트, PostgreSQL 통합 테스트 통과.
5. 모바일 폭에서 접근 가능한 폼과 설치용 manifest. 개인 API는 캐시하지 않음.

## Phase 1

MASTER_SPEC 22장의 다음 단계를 구현한다. 기존 인증·프로필·PWA와 실행 구조를 재사용하고 새 의존성을 추가하지 않는다.

- 할 일: 생성·수정·소프트 삭제·완료·완료 취소, 상태·우선순위·날짜 필터, 날짜/시각 마감과 예상 시간, 버전 충돌 안내.
- 일정: 생성·수정·소프트 삭제, 월/주/일 이동, 종일/시각 일정 구분, 장소·메모, 시간 겹침 안내.
- 홈: 사용자 시간대에 따른 오늘 일정·할 일 집계, 실제 목록과 빠른 입력. 완료를 활동 시간으로 환산하지 않는다.
- PostgreSQL Flyway V2로 기존 사용자 데이터를 보존하며 테이블을 추가한다. 모든 조회·변경은 로그인 계정 소유권으로 제한한다.
- 목록·편집기: 로딩·빈 상태·연결 오류·재시도, 삭제 확인, 충돌 시 초안 보존과 최신 내용 불러오기, 모바일 화면.

### 수용 기준

1. 로그인 후 오늘 할 일을 추가·완료하고 새로고침해도 유지된다.
2. 내일 종일 일정을 추가하고 월/주/일 보기에서 조회·수정·삭제한다.
3. 다른 사용자의 기록은 목록·홈에 나타나지 않으며 수정·삭제할 수 없다.
4. 오래된 버전의 수정·삭제는 409이며, 완료 재요청은 활동을 생성하지 않는다.
5. 종일 종료일 제외 정책, 프로필 시간대의 날짜 경계와 DST를 검증한다.
6. 웹 린트·타입검사·단위 테스트·빌드, PostgreSQL 통합 테스트와 브라우저 흐름을 검증한다. 실제 결과와 미검증 항목은 [VALIDATION.md](VALIDATION.md)에 기록한다.

## 관리자/일반 사용자 분리

- Flyway V3로 ADMIN/USER 역할을 추가하고 기존 계정·신규 가입은 USER로 유지한다.
- 서버의 현재 DB 역할로 관리자 API를 보호하며 회원 메타데이터·가입 초대만 제공한다.
- 공통 로그인 이후 역할별 기본 화면과 관리자 메뉴를 제공한다. 비밀번호·타인의 개인 기록은 노출하지 않는다.
- 최초 관리자는 별도 비밀 값과 일회성 컨테이너로만 구성한다. 기존 USER의 자동 승격·관리자 비밀번호 재설정은 제공하지 않는다.
- 검증 범위: 권한 위조·오래된 세션·익명 접근·개인 데이터 격리, 관리자 초기화 재실행·동시 실행, 모바일 화면·초대 마스킹·장애 복구.

## 후속 단계

Phase 2 이후의 루틴/성장, 원장/예산, 주식, OCR, 이메일 검증/복구는 미구현이다. 반복 일정·외부 캘린더 동기화는 후속 백로그다. 금융·성장에는 예시를 실데이터로 표시하지 않는다. 실기기 Safari/Android 설치와 공개 서버 운영 검증은 배포 후 수행한다.
