# Phase 0–1 보안 정책

- 개인 API는 Spring Security 인증과 검증된 사용자 UUID로 소유권을 제한합니다.
- 앱 권한은 USER/ADMIN이며 모든 가입과 기존 계정의 기본값은 USER입니다. 관리자 API는 매 요청의 현재 DB 역할을 검사하고 세션에 저장된 역할만으로 허용하지 않습니다. ADMIN도 타인의 개인 기록에 접근할 수 없습니다.
- 최초 관리자는 명시적으로 전달한 초기화 이메일·비밀번호로만 생성합니다. 이미 있는 계정의 승격·암호 재설정이나 첫 가입자 자동 관리자 지정은 하지 않습니다. 초기화 비밀 값은 일반 실행 환경·웹 번들·Git·Docker 빌드 컨텍스트에서 제외합니다. 절차는 [권한 문서](ACCESS_CONTROL.md)를 따릅니다.
- 할 일·일정의 목록·상세·집계·변경·삭제는 모두 세션의 `user_id` 조건으로 제한합니다. 수정·삭제 시 버전과 행 잠금으로 동시 변경을 보호하며, 다른 사용자의 ID는 404로 응답합니다.
- 로그인·가입·로그아웃·설정 변경 모두 CSRF 필수. 서버 세션으로 인증하고 로그인 시 세션 ID와 CSRF 토큰을 교체합니다.
- 쿠키는 HttpOnly·SameSite=Lax, prod에서는 Secure. 비활동 만료 7일, 인증 후 절대 만료 30일. 프로세스 재시작 시 세션 소멸.
- 비밀번호는 BCrypt cost12. 가입은 12자 이상·UTF-8 72바이트 이하. 로그인 실패는 이메일 존재 여부를 숨깁니다.
- 로그인 시 IP 및 정규화한 이메일별 15분 동안 최대10회 시도. 단일 인스턴스 메모리 저장소를 사용합니다.
- 공개 가입을 열지 않습니다. 이메일 검증·안전한 복구 경로는 후속 구현입니다. 초대 토큰과 DB 비밀번호를 코드·로그·Git에 넣지 않습니다.
- 서비스워커는 앱 정적 파일만 사전 캐시하고 `/api` 탐색 폴백·개인 API 캐시를 제공하지 않습니다. 브라우저 저장소에 인증 토큰·개인 프로필을 저장하지 않습니다.
- 운영 앱 DB 역할은 슈퍼유저·CREATEDB·CREATEROLE 권한을 갖지 않습니다.

실제 외부 공개 전 이메일·삭제·백업·복구·재인증 등 MASTER_SPEC의 출시 게이트를 검증해야 합니다.

개발 도구 의존성의 audit 경고와 검증하지 못한 항목은 [검증 결과](VALIDATION.md)에 기록합니다. `npm audit --omit=dev` 기준 배포 의존성 취약점은 검증 시점 0개입니다.
